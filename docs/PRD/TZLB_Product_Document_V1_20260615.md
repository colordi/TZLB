## 0. 文档阅读说明

本文将项目分为“当前已具备能力”和“建议迭代能力”两类描述：

- **当前状态**：仓库当前已经描述或实现的能力，例如登录保护、调查候选数据导入、地图视图展示、单条 Word 工作单生成、数据导出、统计接口等。

## 1. 产品概述

### 1.1 产品名称

**林业调查工作台（TZLB，Forest Survey Workbench）**。

### 1.2 产品定位

TZLB 是面向林业有害生物调查、防治工单整理、点位核查和数据导出的网页型内业工具。它的核心价值不是单一的地图展示，也不是单一的 Word 文档生成，而是把“调查数据 -> 点位核查 -> 工单整理 -> 图片归档 -> 标准文档输出 -> 统计导出”串成一个可复用、可扩展、可管控的工作闭环。

### 1.3 当前核心能力

| 能力 | 当前表现 | 产品价值 |
|---|---|---|
| 调查导入 | 按调查日期、害虫类型从 PostgreSQL/PostGIS 读取候选记录，也支持 Excel 上传预览与入库。 | 减少人工复制调查表数据，降低字段录入错误。 |
| 工单生成 | 导入记录后补充描述、备注和图片，逐条生成 Word 工作单。 | 将内业整理工作标准化，减少重复排版。 |
| 地图监测 | 自动枚举 views schema 下带 geom 的地图视图，展示点位、行政区边界和动态筛选器。 | 用空间视角辅助核查点位、属地和危害程度。 |
| 登录保护 | 通过 Cookie 会话和 app_auth.users 用户表控制访问，区分 admin 和 investigator。 | 让工单、导入、导出等敏感能力不向普通调查员暴露。 |
| 数据导出 | 提供 survey / ledger 下表和视图的导出能力。 | 支撑归档、汇总、上报和跨部门数据交换。 |
| 静态托管 | 生产构建后由 FastAPI 直接托管 frontend/dist。 | 降低部署复杂度，适合轻量内网工具。 |

### 1.4 建议产品目标

| 目标 | 建议衡量方式 |
|---|---|
| 降低内业重复劳动 | 单批次工单从“逐条下载”升级为“批量生成 ZIP + 错误清单”。 |
| 降低新增虫种维护成本 | 新增虫种从修改多个前后端文件，收敛为配置注册 + 数据读取器 + 模板。 |
| 提升地图大数据承载能力 | 地图接口支持 bbox、limit、聚合或瓦片化，避免一次性返回全量 GeoJSON。 |
| 提升生产安全性 | 默认密钥、默认密码、非安全 Cookie 在生产环境下启动失败。 |
| 提升可运维性 | 有健康检查、启动自检、日志、审计、备份恢复和数据迁移脚本。 |
| 提升交付可验收性 | 每个模块都有明确输入、输出、异常处理和验收标准。 |

### 1.5 非目标范围

以下能力不建议放入近期核心范围，除非业务部门明确提出：

- 不做完整外业移动端采集 App 替代品；当前项目重点是内业整理和地图核查。
- 不做复杂遥感解译、AI 虫害识别或自动诊断；可作为远期扩展。
- 不做通用 GIS 平台；地图能力应服务于点位核查、筛选、定位和导出。
- 不做复杂组织架构 OA；账户、角色和权限以满足业务边界为主。

## 2. 业务背景与核心问题

### 2.1 典型业务背景

林业有害生物调查通常会形成多源数据：外业调查表、点位基础表、行政区边界、村庄或小区边界、现场照片、历史发生情况、问题点位台账、事件流水等。内业人员需要把这些数据整理成标准格式，并按要求生成防治工单、统计表和地图核查结果。

### 2.2 当前痛点

| 痛点 | 表现 | 影响 |
|---|---|---|
| 数据分散 | 调查表、点位表、图片目录、Word 模板、地图视图分属不同位置。 | 需要人工对照，容易漏字段、错点位、错图片。 |
| 工单整理重复 | 多条记录需要逐条补字段、逐条生成、逐条下载。 | 批量任务效率低，内业人员时间被重复操作消耗。 |
| 虫种扩展成本高 | 新增害虫类型需要改 schema、数据库访问、docgen、前端字段配置和模板。 | 业务扩展越多，维护风险越高。 |
| 地图数据可能膨胀 | 当前以视图为中心返回 GeoJSON，缺少视窗范围、分页或瓦片机制。 | 点位、边界、历史年度图层增加后，页面容易卡顿。 |
| 生产安全依赖人工记忆 | 默认管理员、默认密钥、Cookie 安全配置需要人工覆盖。 | 内网部署容易忽视安全，存在默认账号和会话风险。 |
| 运维可观测不足 | 缺少审计日志、导入批次追踪、生成失败原因汇总。 | 出错后难以追溯是数据、模板、图片还是权限问题。 |

### 2.3 产品设计原则

1. **工作流优先**：功能不是孤立入口，而要围绕“导入、核查、补充、生成、导出、留痕”的业务链路组织。
2. **配置优先**：虫种、字段、模板、图片策略、任务名称、年度代次等变化点应优先配置化。
3. **地图服务业务**：地图能力的目标是快速定位、筛选、核查和导出，不追求通用 GIS 的复杂度。
4. **默认安全**：生产环境不能依赖人工记住改密钥、改密码、开安全 Cookie。
5. **错误可解释**：导入失败、模板失败、图片失败、地图失败都应给出业务可读的原因。
6. **渐进式工程化**：不推倒重写，优先围绕现有 FastAPI + Vue + PostGIS 架构做模块拆分和接口增强。

## 3. 用户角色与权限

### 3.1 角色定义

| 角色 | 标识 | 主要职责 | 默认入口 | 权限边界 |
|---|---|---|---|---|
| 系统管理员 | admin | 管理工单、导入调查数据、导出数据、查看统计、维护配置、管理用户。 | /workorder 或 /dashboard | 可访问所有业务模块。 |
| 调查员 | investigator | 查看地图点位、核查点位空间位置和属性。 | /map | 仅访问地图和与本人角色相关的只读能力。 |
| 业务审核人员 | reviewer，建议新增 | 复核工单、查看统计、下载归档，不直接修改基础配置。 | /dashboard | 可读、可下载、可审核，不能修改系统配置。 |
| 运维人员 | operator，建议新增 | 查看系统健康、日志、备份状态和任务执行状态。 | /system | 不直接修改业务数据。 |

| 模块 | admin | investigator | reviewer 建议 | operator 建议 |
|---|---:|---:|---:|---:|
| 登录 / 退出 | 允许 | 允许 | 允许 | 允许 |
| 地图视图查看 | 允许 | 允许 | 允许 | 可选 |
| 地图筛选 | 允许 | 允许 | 允许 | 可选 |

| 调查候选数据导入 | 允许 | 不允许 | 不允许 | 不允许 |
| Excel 导入入库 | 允许 | 不允许 | 不允许 | 不允许 |
| 工单编辑 | 允许 | 不允许 | 可选只读 | 不允许 |
| 工单生成 | 允许 | 不允许 | 可选下载 | 不允许 |
| 数据导出 | 允许 | 不允许 | 允许 | 可选 |
| 配置中心 | 允许 | 不允许 | 不允许 | 不允许 |

## 4. 用户场景与业务流程

### 4.1 场景一：内业人员生成当天防治工单

**参与角色**：admin。  
**触发条件**：当天调查数据已进入数据库，现场图片已按日期或点位编号归档。  
**主流程**：

1. 登录系统并进入工单工作台。
2. 选择害虫类型、统防统治类型和任务名称。
3. 按调查日期导入候选记录。
4. 勾选本批次需要生成工作单的记录。
5. 补充或修正描述、备注、图片和必要字段。
6. 触发生成工作单。
7. 系统输出 Word 文件或 ZIP 包。
8. 系统记录生成结果、失败原因和下载记录。

**验收标准**：

- 缺少必填字段时不能生成，并能定位到具体记录和字段。
- 缺少图片时按规则提示，但是否阻断生成应由配置决定。
- 批量生成时，成功文件和失败清单应同时可获得。
- 生成文件名应包含害虫类型、编号、调查日期或任务名称，便于归档。

### 4.2 场景二：调查员查看地图点位并核查属地

**参与角色**：investigator 或 admin。  
**触发条件**：调查员需要查看点位位置、危害等级、行政区或参考边界。  
**主流程**：

1. 登录后进入地图页。
2. 选择地图视图，例如美国白蛾调查、国槐尺蠖历年发生情况等。
3. 按属地、调查状态、年份、危害程度等字段筛选。
4. 点击点位查看详情。
5. 切换底图、行政区边界或参考图层。
6. 必要时新增美国白蛾点位或将当前筛选结果导出。

**验收标准**：

- 地图首次加载应有明确加载状态和失败提示。
- 筛选条件应和当前视图字段动态匹配。
- 地图拖动或缩放后，只请求当前视窗范围内的数据。
- 点位详情面板应清楚展示业务字段，不显示 geom 等技术字段。

### 4.3 场景三：管理员导入 Excel 并预检数据质量

**参与角色**：admin。  
**触发条件**：外部调查表以 Excel 形式交付，需要导入 survey 或 ledger 表。  
**主流程**：

1. 上传 .xlsx 文件。
2. 系统执行 dry_run，返回识别到的目标表、总行数、有效行数、错误行、重复记录和字段映射结果。
3. 管理员修正错误或确认导入。
4. 系统入库并生成导入批次记录。
5. 导入结果可在统计和审计中查看。

**验收标准**：

- 仅支持 .xlsx，空文件和格式错误要立即拒绝。
- 预检阶段不能写入业务表。
- 错误必须定位到行号、列名、原值和错误原因。
- 正式入库应具备幂等或重复检测策略。

### 4.4 端到端业务闭环

```text
外业调查 / 外部表格
        ↓
调查数据导入与预检
        ↓
地图核查与空间筛选
        ↓
工单记录补充与图片匹配
        ↓
单条或批量 Word 工作单生成
        ↓
数据导出、统计汇总、审计留痕
        ↓
年度复盘与下轮虫种 / 代次配置
```

**设计理由**：当前项目已经分别具备导入、地图、工单、导出能力。把它们定义为闭环后，后续新增功能就能判断是否服务于闭环，而不是简单堆入口。

## 5. 信息架构与导航设计

### 5.1 当前信息架构

```text
/login
/workorder    管理员：工单录入、调查候选导入、单条生成
/map          管理员与调查员：地图视图、筛选、点位详情、图层切换
```

### 5.2 建议目标信息架构

```text
/login
/dashboard          管理首页：今日任务、异常、统计、快捷入口
/workorder          工单工作台：导入、编辑、校验、生成、下载
/map                地图监测：视图、筛选、图层、详情、导出
/import             调查导入：Excel 预检、确认入库、批次历史
/export             数据导出：表/视图选择、下载记录
/statistics         统计分析：按害虫、属地、日期、危害等级汇总
/config/pests       虫种配置：字段、模板、任务、图片策略
/config/map-views   地图视图配置：展示字段、筛选字段、样式规则
/system/users       用户与角色
/system/audit       审计日志
/system/health      系统健康与启动自检
```

### 5.3 导航规则

| 规则 | 说明 |
|---|---|
| 角色驱动 | 登录后按角色跳转默认页；admin 优先 dashboard，investigator 优先 map。 |
| 工作流优先 | 工单入口要能直接导入、校验、生成，不应让用户在多个页面反复跳转。 |
| 地图工具栏上下文化 | 地图视图、筛选、底图和图层按钮只在 map 页展示。 |
| 异常前置 | 管理首页应突出“缺图片、缺字段、生成失败、导入失败、待处理记录”。 |
| 移动端优先保留地图 | 调查员移动端最常用地图查看和定位；工单批量编辑可主要面向桌面端。 |

**设计理由**：当前 admin 默认进入工单页、investigator 默认进入地图页是合理的。随着导入、导出、统计、配置和审计增加，需要一个 dashboard 作为任务聚合入口，否则功能越多，内业人员越难判断今天该处理什么。

## 7. 模块需求：登录、会话与权限

### 7.1 当前状态

系统通过后端维护 app_auth.users，使用 Cookie 会话保护业务接口。当前角色包括 admin 和 investigator。登录和健康检查不需要登录，地图接口需要有效会话，工单、调查导入、数据导出和统计接口需要管理员角色。

### 7.2 功能需求

| 编号 | 需求说明 | 验收标准 |
|---|---|---|
| AUTH-001 | 用户通过用户名和密码登录。 | 用户名或密码为空时前端阻止提交；错误凭据返回清晰提示；成功后跳转到角色默认页。 |
| AUTH-002 | 登录态基于 HttpOnly Cookie。 | 前端不直接读写会话令牌；刷新页面后可恢复会话。 |
| AUTH-003 | 支持 remember_me。 | 勾选后会话有效期延长，未勾选使用较短会话有效期。 |
| AUTH-004 | 前后端同时执行角色控制。 | 前端隐藏无权限入口；后端拒绝无权限接口请求。 |
| AUTH-005 | 生产环境默认不安全配置必须启动失败。 | AUTH_SECRET_KEY 为默认值、默认管理员密码未改、HTTPS 下未启用 secure cookie 时，生产环境拒绝启动。 |
| AUTH-006 | 登录失败限流。 | 同 IP 或同用户名连续失败超过阈值后延迟或临时锁定。 |
| AUTH-007 | 管理员可修改密码和停用用户。 | 停用用户无法继续登录，已有会话应可被失效。 |
| AUTH-008 | 本地免登只允许开发环境。 | AUTH_BYPASS_LOCALHOST 在 production 下强制无效或启动失败。 |

### 7.3 设计理由

内业系统经常部署在单位内网，容易低估安全风险。该系统包含点位、调查、导出和文档生成能力，默认账号和弱会话配置会放大风险。安全应通过启动检查和后端强制校验落地，而不是只写在 README 中提醒人工修改。

## 9. 模块需求：工单录入与工作单生成

### 9.1 当前状态

当前工单录入页支持选择害虫类型、统防统治任务、按日期导入调查候选记录、编辑记录详情、上传最多 4 张图片，并逐条调用后端接口生成 Word 文件。当前支持的害虫类型包括春尺蠖、国槐尺蠖、美国白蛾和其他害虫。

### 9.2 功能需求

| 编号 | 需求说明 | 验收标准 |
|---|---|---|
| WO-001 | 支持按害虫类型加载对应字段表单。 | 春尺蠖、国槐尺蠖、美国白蛾、其他害虫显示不同字段；必填字段由配置决定。 |
| WO-002 | 支持导入候选记录后批量选择。 | 可全选、反选、删除所选、按字段搜索或过滤。 |
| WO-003 | 支持记录详情编辑。 | 点击行或卡片打开详情；保存后表格同步刷新；未保存时关闭有确认提示。 |
| WO-004 | 支持字段级校验。 | 缺少调查日期、属地、编号、点位名称、详细情况描述时，定位到具体字段。 |
| WO-005 | 支持单条生成。 | 保留当前 /api/workorder/generate 单条能力，用于调试和少量记录导出。 |
| WO-006 | 新增批量生成 ZIP。 | 前端提交多条记录后，系统生成 ZIP；ZIP 内包含成功 Word 文件和失败清单。 |
| WO-007 | 新增批量任务状态。 | 生成中显示进度，完成后显示成功数、失败数、耗时、下载入口。 |
| WO-008 | 支持错误报告。 | 模板字段缺失、图片缺失、图片格式错误、LibreOffice 转换失败等错误可读。 |
| WO-009 | 支持默认输出 docx。 | 默认返回 .docx；如业务确实需要 .doc，可通过配置启用 LibreOffice 转换。 |
| WO-010 | 文件命名规则可配置。 | 支持按害虫类型、任务、编号、调查日期、属地组合命名。 |

### 9.3 批量生成建议流程

```text
用户选择记录
    ↓
前端执行本地字段校验
    ↓
后端执行二次校验
    ↓
创建生成任务 job
    ↓
逐条渲染 docx
    ↓
可选转换 doc
    ↓
打包 ZIP + 错误报告
    ↓
返回下载地址和任务结果
```

### 9.4 批量任务状态建议

| 状态 | 含义 | 前端展示 |
|---|---|---|
| pending | 已创建，等待执行 | 等待生成 |
| running | 正在生成 | 显示进度 x / n |
| partial_success | 部分成功 | 允许下载成功文件和错误报告 |
| completed | 全部成功 | 下载 ZIP |
| failed | 全部失败或系统异常 | 显示失败原因和重试入口 |
| expired | 文件过期已清理 | 提示重新生成 |

### 9.5 设计理由

当前逐条生成更容易实现，也便于调试。但林业内业场景具有明显批量性，一天可能需要处理同一日期、同一虫种、同一任务下的多条记录。批量 ZIP 能显著减少重复下载操作，同时通过错误报告降低排查成本。

## 10. 模块需求：图片上传、校验与匹配

### 10.1 当前状态

工作单记录最多上传 4 张图片。春尺蠖、国槐尺蠖和美国白蛾导入时会尝试按点位编号匹配本地点位截图。美国白蛾生成 Word 时会优先取点位截图，再从 images/{调查日期}/ 中按编号前缀补齐图片。

### 10.2 功能需求

| 编号 | 需求说明 | 验收标准 |
|---|---|---|
| IMG-001 | 单条记录最多 4 张图片。 | 前端和后端均限制，超出后返回字段级错误。 |
| IMG-002 | 限制单图和总大小。 | 例如单图不超过 8 MB，总大小不超过 24 MB；阈值可配置。 |
| IMG-003 | 校验真实图片格式。 | 后端不能只相信 data URL，应解析图片头和实际格式。 |
| IMG-004 | 支持 JPEG、PNG、WebP。 | 非允许格式被拒绝，并提示支持格式。 |
| IMG-005 | 服务端重新编码和压缩。 | 最长边可压缩到 1600px 或配置值，去除 EXIF。 |
| IMG-006 | 图片策略按虫种配置。 | 不同虫种可选择前端上传、磁盘匹配、日期文件夹匹配、点位截图优先等策略。 |
| IMG-007 | 缺图片规则可配置。 | 可设为警告、阻断或允许生成。 |
| IMG-008 | 图片预览和排序。 | 用户可预览、删除、拖拽排序，Word 中按同样顺序插入。 |

### 10.3 图片策略建议

```text
ImageStrategy
    ├── frontend_upload_only
    ├── site_screenshot_first
    ├── date_folder_by_location_id
    ├── white_moth_disk_auto
    └── mixed_manual_and_auto
```

### 10.4 设计理由

图片输入是文档生成最容易出问题的部分：体积过大、格式伪装、EXIF、损坏文件、路径不一致都会导致失败。把图片规则从 docgen 中抽离成策略后，新增虫种或修改匹配规则不会影响其他虫种。

## 12. 模块需求：地图监测与空间核查

### 12.1 当前状态

地图页读取可用地图视图、行政区边界和点位数据。后端会枚举 views schema 下包含 geom 的视图，并将几何统一转换为 WGS84 GeoJSON。前端支持地图视图切换、动态筛选、底图切换、编号标注、点位聚合、点位详情抽屉和美国白蛾点位新增。

### 12.2 功能需求

| 编号 | 需求说明 | 验收标准 |
|---|---|---|
| MAP-001 | 自动列出可用地图视图。 | 仅列出 views schema 下包含 geom 的视图；视图不存在时返回可读错误。 |
| MAP-002 | 按当前视图返回动态筛选项。 | 包含属地、调查状态、年份、危害程度、害虫类型等可用字段。 |
| MAP-003 | 支持 bbox 查询。 | 请求包含 minLng,minLat,maxLng,maxLat 后，只返回视窗内数据。 |
| MAP-004 | 支持 limit 和超限提示。 | 超过阈值时返回 has_more 或 summary，前端提示缩小范围。 |
| MAP-005 | 支持点位聚合。 | 低缩放级别自动聚合，高缩放级别显示具体点位。 |
| MAP-006 | 支持参考图层开关。 | 行政区、小区、村庄、国槐图层等可独立开关。 |
| MAP-007 | 支持编号和名称搜索。 | 输入编号、点位名称或属地后定位到匹配点位。 |
| MAP-008 | 支持当前视窗导出。 | 可导出当前筛选和视窗范围内的 GeoJSON 或 Excel。 |
| MAP-009 | 支持从点位跳转工单。 | admin 点击点位后可选择“生成/编辑工单”。 |
| MAP-010 | 支持新增美国白蛾点位。 | 编号规则校验、重复校验、坐标校验和属地自动识别均可用。 |

### 12.3 地图接口建议

| 接口 | 说明 |
|---|---|
| GET /api/map/views | 列出地图视图。 |
| GET /api/map/views/{view_name}/filter-options | 返回当前视图可筛选字段和选项。 |
| GET /api/map/views/{view_name}?bbox=...&zoom=...&limit=... | 返回当前视窗内 GeoJSON。 |
| GET /api/map/views/{view_name}/summary?bbox=... | 返回当前视窗统计摘要。 |
| GET /api/map/views/{view_name}/clusters?bbox=...&zoom=... | 返回聚合点。 |
| GET /api/map/views/{view_name}/mvt/{z}/{x}/{y} | 远期可选，返回矢量瓦片。 |
| GET /api/map/reference-layers | 列出参考图层。 |
| GET /api/map/reference-layers/{layer_name}?bbox=... | 返回参考图层 GeoJSON。 |

### 12.4 性能要求

| 场景 | 目标 |
|---|---|
| 地图初次加载 | 常规数据量下 2 秒内出现底图和加载状态，5 秒内完成首屏数据。 |
| 筛选变更 | 筛选提交后 3 秒内返回或给出超限提示。 |
| 大数据视图 | 不允许默认全量返回，应通过 bbox、limit、聚合或瓦片化控制。 |
| 点位标注 | 高缩放级别显示编号，低缩放级别不渲染大量文字标签。 |

### 12.5 设计理由

空间数据系统的性能瓶颈通常出现在“全量 GeoJSON 返回 + 前端一次性渲染”。bbox 查询和空间索引是地图工作台最重要的底层优化。地图不是只看点，还应该承载筛选、定位、导出和工单联动。

## 14. 模块需求：虫种配置中心

### 14.1 当前问题

当前新增害虫类型需要同步修改多个前后端文件和模板，维护成本较高。建议将害虫类型、任务、字段、模板、图片策略、地图视图关键字和校验规则集中到“虫种注册表”。

### 14.4 功能需求

| WorkOrderRecord | 工单记录。 | survey_date、locality、location_id、location_name、description、images |
| WorkOrderJob | 批量生成任务。 | job_id、status、total、success、failed、created_by、created_at |
| WorkOrderArtifact | 生成结果文件。 | job_id、filename、format、path、expires_at、size |
| MapView | 地图视图。 | name、columns、filter_fields、geometry_type、srid |
| ReferenceLayer | 参考图层。 | name、display_name、geom、style_rule |
| WhiteMothSite | 美国白蛾点位。 | code、site_name、locality、longitude、latitude、geom |
| SurveyImportBatch | 调查导入批次。 | batch_id、file_name、dry_run、total_rows、valid_rows、invalid_rows |
| AuditLog | 审计日志。 | actor、action、target、result、ip、created_at、details |

### 15.2 数据库建议

| 主题 | 建议 |
|---|---|
| 主键 | 使用 identity 或 sequence，减少手工 MAX(id)+1。 |
| 空间索引 | 所有高频 geom 字段建立 GiST 索引。 |
| 查询索引 | 属地、调查日期、编号、害虫类型、危害程度等筛选字段建立 B-tree 索引。 |
| 年度表 | 短期保留现有年度表，长期逐步引入 year、generation 字段减少复制表。 |
| 迁移 | 引入 migrations 目录和迁移执行脚本，记录表结构演进。 |
| 备份 | 将数据库备份、模板备份、图片目录备份分开定义。 |

### 15.3 数据质量规则

| 规则 | 说明 |
|---|---|
| 编号唯一性 | 点位基础表中的编号应按虫种或点位类型维持唯一。 |
| 坐标合法性 | 经度 -180 到 180，纬度 -90 到 90，入库前转为 PostGIS geom。 |
| 日期格式 | 调查日期统一 YYYY-MM-DD。 |
| 危害程度 | 使用标准枚举或配置映射，不应混用多个同义值。 |
| 图片关联 | 图片与记录通过编号、调查日期或用户上传显式关联。 |
| 模板字段 | Word 模板占位字段必须能从记录或配置中找到映射。 |

## 19. 工程化与架构优化建议

### 19.1 后端模块拆分

当前数据库访问层承担了连接、地图、候选数据、GeoJSON、图片读取和业务描述等多种职责。建议拆分如下：

```text
  identifiers.py

  pest_registry.py
  map_service.py
  workorder_service.py
  image_service.py
  document_service.py
  import_service.py
```

**设计理由**：拆分不是为了追求形式，而是为了让地图、导入、工单、图片和配置可以独立测试、独立演进。

### 19.2 前端模块拆分

建议将大型页面拆成组件和 composables：

```text
components/map/
  MapCanvas.vue
  LayerSwitcher.vue
  FilterPanel.vue
  FeatureDrawer.vue
  WhiteMothSiteCreateDrawer.vue
  useMapLayers.js
  useMapFilters.js

components/workorder/
  PestSelector.vue
  CandidateImportDialog.vue
  RecordTable.vue
  RecordEditorDrawer.vue
  ImagePicker.vue
  BatchGeneratePanel.vue
  ValidationSummary.vue
```

**设计理由**：地图和工单页已经具备复杂工作台特征。继续在单文件中增加状态、请求、地图对象和业务规则，会提高回归风险。

### 19.3 渐进式 TypeScript

建议先从类型定义和 API 层开始：

```text
frontend/src/types/auth.ts
frontend/src/types/map.ts
frontend/src/types/workorder.ts
frontend/src/types/pest.ts
frontend/src/api/*.ts
```

**设计理由**：TZLB 的字段多、中文字段多、虫种差异多。类型化能减少接口字段和模板字段不一致造成的运行时错误。

### 19.4 测试与 CI

| 范围 | 建议 |
|---|---|
| 后端 | 跑单元测试、接口测试、模板字段测试、图片校验测试、地图 bbox 测试。 |

### 20.3 Docker Compose 建议

| 服务 | 说明 |
|---|---|
| postgres-postgis | 数据库服务，启用 PostGIS，挂载数据卷。 |
| backend | FastAPI 服务，挂载模板、点位截图、图片目录和导出目录。 |
| frontend-build | 可选构建阶段，生成 dist 后交给 backend 或 nginx。 |

### 20.4 启动自检清单

| 检查项 | 失败处理 |
|---|---|
| DATABASE_URL 可连接 | 启动失败并输出连接错误。 |
| PostGIS 可用 | 启动失败，提示安装或启用扩展。 |
| app_auth、survey、ledger、reference、sites、views schema 存在 | 启动失败或进入只读降级模式。 |
| 核心模板文件存在 | 工单模块标记不可用，并提示缺失模板。 |
| 图片目录可读写 | 图片上传和自动匹配功能不可用。 |
| LibreOffice 可执行 | 如果启用 doc 转换则启动失败；如果默认 docx 可降级运行。 |
| AUTH_SECRET_KEY 非默认值 | production 下启动失败。 |
| 默认管理员密码已修改 | production 下启动失败。 |

### 20.5 设计理由

这个项目的运行依赖较多：数据库、空间扩展、模板、图片目录、LibreOffice 和前端静态资源。启动自检能把“用户点击时才报错”提前到部署阶段发现。

## 23. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 年度表和虫种表继续增加 | 代码和数据库维护成本上升。 | 引入 pest_registry、year、generation 配置和迁移脚本。 |
| 地图数据持续膨胀 | 前端渲染和后端查询变慢。 | bbox、limit、聚合、空间索引、远期 MVT。 |
| Word 模板频繁变化 | 生成失败和字段缺失增加。 | 模板字段自动校验，错误报告明确字段名。 |
| 图片目录命名不稳定 | 自动匹配失败。 | 图片策略配置化，提供上传日期文件夹和手动补图能力。 |
| 默认账号或密钥未修改 | 安全风险。 | 生产环境启动检查强制失败。 |
| 用户角色过少 | admin 权限过大。 | 渐进新增 reviewer、operator，不影响当前两级角色。 |
| 部署环境差异 | LibreOffice、字体、路径和权限问题。 | Docker Compose、启动自检、默认 docx 输出。 |

## 25. 总结

TZLB 当前已经具备一个实用的林业内业工作台雏形：它能连接 PostgreSQL/PostGIS，能读取调查候选数据，能展示空间点位，能生成 Word 工作单，能通过角色区分管理员和调查员。下一阶段的关键不是重写技术栈，而是把业务变化点收束起来，把批量工作流补齐，把地图查询从全量转为视窗化，把生产安全和运维能力前置。

建议优先落地三条主线：

1. **虫种配置化**：解决新增虫种、年度和模板变化的长期维护问题。
2. **地图 bbox 化**：解决空间数据增长后的性能问题。
3. **工单批量化**：解决内业人员高频重复操作问题。

完成这三条主线后，TZLB 会从“能用的工具”升级为“可长期维护、可扩展到更多虫种和年度任务、可稳定部署的林业内业工作台”。
