# 年份与世代扩展改造方案

> 状态:方案设计稿(待评审)
> 编制日期:2026-07-05
> 适用项目:TZLB 林业调查工作台(FastAPI + Vue3 + Leaflet + PostgreSQL/PostGIS)

---

## 一、背景与现状诊断

### 1.1 问题

年份和世代在系统里**不是可配置维度**,而是硬编码在三层中:

- **数据库层**:表名/视图名带 `2026年`/`第一代`(`survey."美国白蛾第一代调查表"`、
  `ledger."2026年美国白蛾第一代问题点位事件流水表"`、`views."2026_美国白蛾第 1 代调查"`);
  sites 表用宽字段编码年份(`国槐尺蠖_2026年_幼虫发生情况`)
- **后端配置层**:`backend/services/pest_registry.py:121-123,151` 的 `tasks` 元组硬编码
  `"2026..."`;`backend/db/postgres.py:31` 把美国白蛾调查表名写死为第一代
- **前端配置层**:`frontend/src/components/workorder/fieldConfig.js` 镜像后端 `tasks` 硬编码,
  美国白蛾任务下拉只有 1 个 option

**唯一显式年份列**只出现在 `views."国槐尺蠖幼虫历年发生情况"`(用 LATERAL VALUES 展开
sites 宽字段),且 `frontend/src/views/MapView.vue:840` 注释表明通用筛选组件 MapToolbar 已
被移除,**前端 UI 完全没接上这个筛选维度**(后端 `buildMapQueryParams` 早已支持,
`frontend/src/api/__tests__/map.spec.js:22-39` 测试覆盖年份场景)。

### 1.2 后果

扩展 2027 年或美国白蛾第二代,要新建调查表 + 新建 ledger 表 + 新建/重建视图 + 改 sites
宽字段 + 改前后端常量。配置无法复用,违背"高度重复化"的实际。

### 1.3 已确认的决策边界(用户决策)

| 维度 | 决策 |
|---|---|
| 数据库迁移策略 | **接受破坏性迁移**:合并表+显式年份/世代列,一次性迁移历史数据,长期零 DDL 扩展 |
| sites 宽字段处理 | **sites 精简为纯点位静态属性**,移除所有年度宽字段;历年数据直接通过 sites↔survey 关联获取 |
| 美国白蛾世代模型 | **共用一张表+世代列**:`survey."美国白蛾调查表"` 一张表,用 `世代` 列区分第一/二/三代 |
| reference 历史汇总 | **直接丢弃不迁**:`25年1/2/3代受害株`、`25年景观害虫发生` 4 个宽字段直接 DROP COLUMN |
| 春尺蠖点位状态 | **不新增点位年度资格表**,把 `春尺蠖_2026年成虫发生情况` 改为静态字段 `当前点位状态`,可选值:可调查、不可调查、伐除;历史年份宽字段数据丢弃 |

## 二、总体策略

| 层 | 改造方向 |
|---|---|
| survey | 各害虫调查表合并为单表,加 `年份 int NOT NULL` 列;美国白蛾加 `世代 text NOT NULL` 列;国槐尺蠖把"第一/二/三代"从 task 名抽出为 `世代` 列;主键统一含 `年份`(+`世代`) |
| ledger | 事件流水表合并为单表,加 `年份`/`世代` 列;台账视图按列聚合,表名去年度前缀 |
| sites | 精简为纯点位静态属性(编号/geom/属地/点位名称/村/寄主树种/地块类型等);`杨树点位基础表` 的两个春尺蠖宽字段合并为静态字段 `当前点位状态`;移除所有年度宽字段 |
| reference | 清理 `通州区小区边界` 的 4 个 `25年...` 宽字段(当前视图已无引用),数据丢弃 |
| views | 去年度前缀,暴露 `年份`/`世代` 字段供筛选;历年视图改为 JOIN survey 按年份聚合 |
| pest_registry / fieldConfig | `tasks` 改模板,year/gen 作为运行时参数;新增 `generations` 字段 |
| 前端 | 加 year/generation 选择器;接入后端早已返回的 `年份`/`世代` filter_fields |

## 三、需移除/承接的宽字段清单

| 表.字段 | 语义 | 承接方案 |
|---|---|---|
| `sites."国槐点位基础表"."国槐尺蠖_2024/2025/2026年_幼虫发生情况"` | 历年危害程度汇总 | 历年数据丢弃;由 `survey."国槐尺蠖幼虫调查表"`(加 `年份` 列)关联推导 |
| `sites."杨树点位基础表"."春尺蠖_2026年成虫发生情况"` ('伐') | 点位已伐树标记 | 合并到新静态字段 `当前点位状态`(值:`伐除`) |
| `sites."杨树点位基础表"."春尺蠖_2026年_围环发生情况"` ('可调查') | 围环调查资格标记 | 合并到新静态字段 `当前点位状态`(值:`可调查`/`不可调查`) |
| `reference."通州区小区边界"."25年1/2/3代受害株"` | 2025 历史汇总 | 直接 DROP COLUMN,数据丢弃 |
| `reference."通州区小区边界"."25年景观害虫发生"` | 2025 历史汇总 | 同上 |

### 3.1 `当前点位状态` 字段语义

`sites."杨树点位基础表"` 新增静态字段 `当前点位状态 varchar`,可选值:
- `可调查`:点位正常,可安排各类调查
- `不可调查`:暂不安排围环/成虫调查(幼虫调查仍可纳入)
- `伐除`:树木已伐除,全部排除

视图过滤逻辑映射:

| 视图 | 旧 WHERE | 新 WHERE |
|---|---|---|
| `views."春尺蠖幼虫调查"` | `s."春尺蠖_2026年成虫发生情况" <> '伐'` | `s."当前点位状态" <> '伐除'` |
| `views."春尺蠖成虫调查"` | `s."春尺蠖_2026年_围环发生情况" = '可调查'` | `s."当前点位状态" = '可调查'` |

数据迁移规则(从旧宽字段值映射到新字段值):
- `春尺蠖_2026年成虫发生情况 = '伐'` → `当前点位状态 = '伐除'`
- `春尺蠖_2026年_围环发生情况 = '可调查'` → `当前点位状态 = '可调查'`
- 二者冲突时以"伐"优先(已伐树则整体伐除)
- 其它值/为空 → `当前点位状态 = '不可调查'`(默认值)

## 四、分阶段实施

### 阶段 1:配置层去硬编码(不动数据库,向前兼容)

让 year/gen 成为应用层一等公民;此阶段只有 `year=2026 且 gen=第一代` 能正常工作,
其它值报"该年度/世代尚未配置"。阶段 2 完成后解锁任意 year/gen。

**后端**

- `backend/services/pest_registry.py`
  - `tasks: tuple[str,...]` → 改为 `task_template: str`(如 `"{{year}}{{pest}}{{generation}}防治"`)
    + `generations: tuple[str|None, ...]`(默认 `(None,)`,美国白蛾/国槐尺蠖设
    `("第一代","第二代","第三代")`)
  - 新增 `build_task(entry, year, generation) -> str` 渲染函数
  - `validate_task_type` 逻辑不变(仍校验 `control_type`);新增 `validate_task` 校验
    渲染后的 task 字符串
- `backend/schemas.py`
  - `WorkOrderGenerateRequest` / `BatchGenerateRequest` 增
    `year: int = Field(default_factory=lambda: datetime.now().year)`、
    `generation: str | None = None`
  - `WorkOrderRecord` 不变
  - 新增校验:`generation` 必须在 `pest_config.generations` 范围内
- `backend/routers/survey.py` + `backend/db/postgres.py`
  - `/api/survey/candidates` 增 `year`、`generation` query 参数
  - 调查表名常量改为按 `year`/`generation` 解析的函数(此阶段仍硬编码返回 2026/第一代的表名)
- `backend/services/docgen.py:349-350, 537-539`
  - 输出文件名从 `datetime.now().year` 改为 `payload.year`

**前端**

- `frontend/src/components/workorder/fieldConfig.js`
  - 镜像后端结构:`taskTemplate` + `generations`
- `frontend/src/views/WorkOrderView.vue`
  - 增年份选择器(默认当前年)和世代选择器(当 `generations != [None]` 时显示)
  - `taskName` 由 `taskTemplate` + 所选 year/generation 客户端渲染
- `frontend/src/api/workorder.js` / `survey.js`
  - payload 增加 `year`、`generation` 字段

### 阶段 2:数据库合并迁移(核心破坏性变更)

**前置:备份整库。** 所有迁移写成新迁移文件,按顺序执行。

**步骤 1:新建合并版调查表**(保留旧表暂不删,并行存在)

- `survey."美国白蛾调查表"`:字段同旧 `美国白蛾第一代调查表`,加 `年份 int NOT NULL`、
  `世代 text NOT NULL`,主键 `(编号, 调查日期, 年份, 世代)`,CHECK `世代 IN ('第一代','第二代','第三代')`
- `survey."国槐尺蠖幼虫调查表"`:加 `年份 int NOT NULL`、`世代 text NOT NULL`,
  主键 `(编号, 调查日期, 年份, 世代)`
- `survey."春尺蠖幼虫调查表"` / `survey."春尺蠖成虫调查表"` / `survey."春尺蠖围环调查表"`:
  各加 `年份 int NOT NULL`,主键加 `年份`
- `survey."其他害虫调查表"`:加 `年份 int NOT NULL`,主键 `(编号, 虫害类型, 调查日期, 年份)`

**步骤 2:sites 表精简**

- `sites."杨树点位基础表"`:
  - 新增 `当前点位状态 varchar NOT NULL DEFAULT '不可调查'`,CHECK 值在
    (`可调查`/`不可调查`/`伐除`)内
  - 按第三节数据迁移规则,从 `春尺蠖_2026年成虫发生情况` + `春尺蠖_2026年_围环发生情况`
    两个宽字段计算并回填 `当前点位状态`
  - DROP 两个宽字段
- `sites."国槐点位基础表"`:DROP 3 个 `国槐尺蠖_20XX年_幼虫发生情况` 宽字段(数据丢弃)
- 其它 sites 表无宽字段,不动

**步骤 3:reference 表清理**

- `reference."通州区小区边界"`:DROP 4 个 `25年...` 宽字段,数据丢弃

**步骤 4:数据迁移**

- 旧 `美国白蛾第一代调查表` 全量 INSERT 到新表,`年份=2026`、`世代='第一代'`
- 旧 `国槐尺蠖幼虫调查表` 数据 INSERT,`年份` 从 `调查日期` 提取,`世代` 暂统一填 `'第一代'`
  (旧表无世代区分;若需精确区分需人工核对)
- 旧春尺蠖三张表数据 INSERT,`年份` 从 `调查日期` 提取
- 旧其他害虫表数据 INSERT,`年份` 从 `调查日期` 提取

**步骤 5:ledger 合并**

- 新建 `ledger."美国白蛾问题点位事件流水表"`:加 `年份 int`、`世代 text`,主键调整
- 旧 `2026年美国白蛾第一代问题点位事件流水表` 数据迁入(年份=2026、世代='第一代')
- 其它害虫的 `2026年...事件流水表` 同理加 `年份` 列迁入

**步骤 6:视图重建**(去年度前缀,按列筛选)

- `views."美国白蛾调查"`(替代 `2026_美国白蛾第 1 代调查`):JOIN
  `reference."通州区小区边界"` + `survey."美国白蛾调查表"`,输出 `年份`/`世代`/`调查日期`
- `views."国槐尺蠖幼虫历年发生情况"`:CROSS JOIN LATERAL 改为 JOIN
  `survey."国槐尺蠖幼虫调查表"` 按年份聚合,输出 `年份`/`世代`/`危害程度`
- `views."春尺蠖幼虫调查"` / `views."春尺蠖成虫调查"`:WHERE 子句改为按
  `当前点位状态` 过滤(映射规则见第三节)
- `views."国槐尺蠖幼虫调查"` / `views."其他害虫调查"`:去掉视图名年度前缀,输出加 `年份` 字段

**步骤 7:触发器重建**

- `survey.sync_meiguobaie_event_from_inspection` 等触发器改为指向新合并表,
  且 `年份`/`世代` 透传到 ledger 事件流水

**步骤 8:后端常量更新**

- `backend/db/postgres.py:31` `MEI_GUO_BAI_E_SURVEY_TABLE = "美国白蛾第一代调查表"`
  → 改为 `"美国白蛾调查表"`,所有调查表名常量去年度/世代后缀
- `backend/services/survey_excel_import.py:22-23` 同步更新
- 调查候选查询 SQL 增 `年份`/`世代` WHERE 条件

**步骤 9:DROP 旧对象**(确认数据迁完后)

- 旧分年度/分世代调查表、ledger 表、视图

### 阶段 3:前端补齐筛选 UI

## 五、风险与注意事项

1. **国槐尺蠖旧调查数据无世代区分**:旧表不分区世代,迁移时统一填 `'第一代'` 可能与
   实际不符。需确认旧数据是否真都是第一代,或保留为"世代未知"占位值。
2. **`当前点位状态` 语义合并**:两个旧宽字段合并为一个三态字段,数据迁移规则按"伐优先"
   处理。迁移完成后需抽样核对点位状态是否与历史调查行为一致。
3. **触发器依赖**:`survey.sync_*_event_from_inspection` 触发器在调查表 INSERT 时同步写
   ledger 事件流水。合并表后触发器需重写,且要带 `年份`/`世代` 透传。
4. **数据库实况可能还有代码未引用的宽字段**:迁移前必须跑 `information_schema.columns`
   全量盘点 sites/reference 各表,避免漏删。
5. **历史数据丢弃的不可逆性**:国槐历年发生情况、reference 25年代次汇总一旦 DROP 即
   不可恢复。建议迁移前对涉及丢弃的宽字段做一次 `pg_dump` 表级备份归档,既不混入主表
   也保留可恢复副本。
