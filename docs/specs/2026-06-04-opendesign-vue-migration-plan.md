# OpenDesign 高保真原型迁移至 Vue 3 + Vite 计划

## 1. 背景与目标

`design-preview/` 提供了林业调查工作台的高保真 HTML/CSS 原型：

- `index.html`：工作概览与入口页
- `login.html`：登录页
- `workorder.html`：调查工单页
- `map.html`：调查点位地图页
- `assets/app.css`：共享视觉样式
- `DESIGN.md`：设计 token、组件规则和响应式规范

当前 `frontend/` 已是 Vue 3 + Vite 应用，并包含真实认证、权限、API、Leaflet 地图、工单生成和测试。迁移不能使用静态原型覆盖现有行为层，应先完成隔离的静态 Vue 页面和样式还原，再另行评审是否将视觉层接入现有业务页面。

本计划当前只执行第一阶段：静态 Vue 页面与样式还原。

## 2. 当前阶段边界

### 2.1 必须完成

- 将 OpenDesign HTML 结构迁移为 Vue 单文件组件。
- 建立单一设计 token 体系。
- 按页面逐个完成高保真视觉还原。
- 使用本地静态 fixture 渲染页面状态。
- 完成桌面端和移动端响应式还原。
- 保留必要的纯前端展示交互，例如展开、关闭、选中和切换。
- 每完成一个页面即独立验收，不一次性生成全部页面。

### 2.2 明确不做

- 不连接真实 API。
- 不调用现有 `src/api/**`。
- 不读取或写入真实认证会话。
- 不修改后端、数据库或接口契约。
- 不实现真实工单生成、导入、下载、上传或地图查询。
- 不将 OpenDesign 的模拟数据混入真实 store。
- 不用静态模拟地图替换现有 Leaflet 实现。
- 不在第一阶段直接替换现有 `/login`、`/workorder`、`/map` 生产路由。

## 3. 迁移原则

### 3.1 展示层与行为层隔离

第一阶段新增独立预览路由和静态 fixture。预览页面只依赖 Vue、Vue Router、图标组件和本地样式，不依赖 API、认证 composable、业务 store 或下载工具。

建议预览路由：

| 路径 | 页面 |
|---|---|
| `/design/login` | 登录页静态预览 |
| `/design/overview` | 工作概览静态预览 |
| `/design/workorder` | 工单页静态预览 |
| `/design/map` | 地图页静态预览 |

预览路由统一设置：

- `requiresAuth: false`
- `hideShell: true`
- 仅作为视觉迁移和评审入口

### 3.2 保留现有业务实现

以下现有能力在第一阶段不改动：

- `frontend/src/api/**`
- `frontend/src/auth/**`
- `frontend/src/composables/useAuthSession.js`
- `frontend/src/stores/mapStore.js`
- `frontend/src/components/map/LeafletMap.vue`
- 现有生产路由守卫
- 工单导入、编辑、导出和图片处理逻辑

### 3.3 每次只迁移一个页面

每个页面按照“结构迁移、样式还原、响应式检查、构建测试、人工验收”的顺序完成。页面未验收前，不开始下一个页面。

## 4. 设计 Token 策略

### 4.1 应保留的 Token

保留 `design-preview/DESIGN.md` 中定义的以下视觉体系：

- 颜色：背景、表面、文本、弱文本、边框、主色、导航色、状态色和地图色。
- 字体：展示字体、正文字体、等宽数字字体。
- 字号与行高。
- 间距。
- 圆角。
- 阴影。
- 控件高度。
- 动效时长与缓动。
- `1180px`、`920px`、`680px`、`430px` 响应式断点规则。

同时保留当前项目真实地图所需的：

- `--risk-*`
- 地图边界色
- Leaflet 点位和聚合颜色

### 4.2 Token 命名决策

以语义明确的长名称作为唯一标准：

```css
--color-bg
--color-surface
--color-text
--color-text-muted
--color-border
--color-primary
--color-nav
--color-info
--color-warning
--color-danger
```

不长期保留 OpenDesign 中的 `--bg`、`--fg`、`--accent`、`--nav` 等短名称，避免与当前 `styles.css` 形成两套事实源。

### 4.3 建议样式文件

```text
frontend/src/styles/
├── tokens.css
├── reset.css
├── primitives.css
└── design-preview.css
```

- `tokens.css`：唯一 token 来源。
- `reset.css`：基础元素重置。
- `primitives.css`：按钮、输入框、徽标、面板等基础样式。
- `design-preview.css`：预览页壳层和仅供静态迁移使用的布局样式。

第一阶段不立即删除当前 `frontend/src/styles.css`，避免影响现有生产页面。新样式先限制在设计预览壳层内，视觉接入阶段再合并和清理旧样式。

## 7. OpenDesign 代码复用边界

### 7.1 可以复用

- `DESIGN.md` 中的视觉规范。
- CSS 属性值、布局比例、断点和响应式行为。
- 语义化 HTML 层级。
- 登录背景装饰、侧边栏布局、卡片、表格和抽屉视觉结构。
- 静态文案和示例数据，放入隔离 fixture。
- 少量品牌专用 SVG。

### 7.2 不应该复用

- `querySelector`、`addEventListener`、`innerHTML` 和直接 DOM 修改。
- `location.href` 和静态 `.html` 链接。
- 原型中的 `setTimeout` 假流程。
- 原型中的固定用户、日期、数量和状态作为业务数据。
- 整份复制 `design-preview/assets/app.css`。
- ID 选择器、页面内联样式和页面内 `<style>` 整块搬运。
- 地图中的假底图、绝对定位标记和模拟聚合点作为正式地图实现。
- 原型中当前系统并不存在的统计分析、风险热力和审批状态能力。

## 8. 静态 Fixture 约定

建议统一存放：

```text
frontend/src/fixtures/design/
├── workorders.js
├── mapPoints.js
└── navigation.js
```

约束：

- fixture 必须明确标注为设计预览数据。
- 不从 API 或 store 获取数据。
- 页面组件不得在内部散落大段硬编码数据。
- fixture 字段只服务视觉展示，不定义真实业务契约。
- 不模拟成功响应、认证结果或下载结果。

## 12. 主要风险与控制措施

### 12.1 全局 CSS 冲突

风险：OpenDesign 与当前项目都使用 `.app-shell`、`.panel`、`.btn` 等常见类名。

控制：第一阶段样式限定在 `.design-preview-root` 下；不直接导入整份 `app.css`。

### 12.2 两套 Token 长期并存

风险：短名称和长名称变量并存，后续难以判断真实来源。

控制：新样式只使用长名称 token；第一阶段结束时检查重复变量。

### 12.3 预览数据污染业务模型

风险：原型中的状态、统计和字段与真实业务不一致。

控制：所有模拟数据放入 `fixtures/design/`，并禁止正式页面导入。

### 12.4 误改现有业务行为

风险：当前项目已有大量认证、地图和工单行为测试。

控制：使用独立预览路由；第一阶段不替换现有正式页面；每阶段运行完整前端测试。

### 12.5 地图实现被错误替换

风险：原型地图仅用于视觉展示，不具备真实 Leaflet 能力。

控制：静态地图组件命名为 `MapMockCanvas.vue`；禁止修改或替换 `LeafletMap.vue`。

### 12.6 浏览器视觉兼容

风险：OKLch、`color-mix()`、宋体字体栈在不同环境中的表现可能不同。

控制：在目标浏览器中验证；必要时为关键颜色提供回退值，但不新增第二套主题。
